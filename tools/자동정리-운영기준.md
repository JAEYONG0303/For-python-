# 자동 정리 및 커밋 운영 기준

- 하루 최대 3개 노트북을 수업 순서로 정리한다. 쉬었던 날의 분량을 몰아서 처리하지 않는다.
- 신규 자동 커밋은 하루 한 번이다. 이미 만든 커밋의 push 재시도는 횟수 제한과 분리한다.
- 원격 조회나 정리에 실패하면 신규 커밋을 중단하고 로그를 남긴다. 부분 수정 파일은 삭제하거나 되돌리지 않고 검토를 위해 보존한다.
- 코드와 Markdown 원문은 공백까지 보존한다. 문자열, 수식, 출력, 실행번호, 첨부파일을 자동으로 수정하지 않는다.
- 기존 커널 및 Python 버전 정보는 유지한다. 실제 재실행 없이 버전을 변경하지 않는다.
- 내용·출력·첨부·메타데이터·실행번호가 없는 마지막 빈 셀만 제거할 수 있다.
- 정리 결과는 nbformat 스키마 검증을 통과해야 한다. 빈 파일을 빈 노트북으로 만드는 것은 손실된 수업 내용의 복구를 의미하지 않는다.
- 미리보기는 노트북, 진행 기록, Git 인덱스를 변경하지 않는다. 실행 로그만 추가한다.
- 기존 변경분도 자동 커밋 대상이다. 공개하면 안 되는 파일은 작업 전에 .gitignore에 지정한다.
- PC가 꺼져 있거나 로그아웃한 동안의 실행은 보장하지 않는다. 성공 여부는 실행 로그와 원격 커밋으로 확인한다.

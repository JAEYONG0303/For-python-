## 1. 오늘 배운 내용

- **데이터 수집**
    - 여러 형태의 데이터가 여러가지 기술로 전송됨

- **데이터 전송**
    - 벌크(bulk)형
        ■ 존재하는 데이터를 정리해 추출하는 방법
        ■ DW에서는 주로 벌크형
    - 스트리밍(streaming)형
        ■ 실시간으로 데이터륿 보내는 방법
        ■ 모바일 애플리케이션, 임베디드 장비 등에서 사용
        ■ 빅데이터 세계에서는 스트림 처리(실시간 처리)형 방식으로 처리
        ■ 장기적 데이터 분석에는 적합하지 않음(데이터 양이 너무 많아짐)
    
    ---> 그래서 **분산 시스템** + **배치처리 구조**의 필요성 증대

- **분산 스토리지**
    - (여러 컴퓨터 + 디스크)로 구성된 시스템
    - 객체 스토리지가 대표적(한 덩어리에 이름 부여하여 파일로 저장 ex. Amazon S3)
    - NoSQL DB도 가능 ---> 어플리케이션 데이터(로그..인감...?) 측면

- **분산 데이터 처리**
    - MapReduce: 많은 데이터를 나눠서 처리한 뒤, 같은 항목끼리 결과를 합치는 방식      <-> HDFS: 저장담당
        ■ 여러 컴퓨터에서 동시 수행 가능
        ■ 하둡의 분산 배치 프레임워크
        ■ SQL 작성 -> HIVE가 해석 + 계획 -> MapReduce가 여러 서버에서 나누어 계산 -> 결과 반환 
    - ETL VS ELT
        ■ 차이점: 추출 -> 변환 -> 적재     VS     추출 -> 적재 -> 변환

## 1. 오늘 배운 내용

- **워크플로 관리**
    - 한 곳에서 제어 -> 전체 움직임 파악

- **DW, DM**
    - DATA SOURCE(LOW DATA) -> DW(장기 보존용 정리 테이블) -> DM(일부 추출 테이블, 성격을 띔)
                               DL(단순 스토리지, 이때 MAPREDUCE가 사용)
    - DW를 중심으로 하는 파이프라인은 테이블 설계, ETL 프로세스가 중요

- **ad hoc 분석**
    - 수작업 데이터 집계
    - DL과 DW에 직접 연결하는 경우가 많음
* 결국 데이터를 어떤 구조로 관리하고 활용하느냐에 따라 갈림

- **기간계 VS 정보계**
    - 기간계: 실제 업무 처리하는 시스템
    - 정보계: 쌓인 데이터를 보고 판단하는 시스템
